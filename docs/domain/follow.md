# Follow

Follow is Geek's directed, lightweight collector-to-collector graph edge. It is
not friendship, does not require reciprocity, and has no pending or approval
state. Reciprocal follows are ordinary independent edges.

## Identity and integrity

Both ends reference `profiles.id`, Geek's canonical collector identity. Profile
IDs share the authenticated user's UUID without turning authentication metadata
into a second social identity.

The `follows` table is the single source of truth. Its composite primary key
allows at most one `(follower_id, followed_id)` edge, including under concurrent
writes. A check constraint prohibits self-follow. Both profile foreign keys use
cascade deletion so account/profile lifecycle cannot leave orphaned edges.
`created_at` is generated by the database.

## Access and privacy

Follow graph reads are authenticated-only in V1. They join only the existing
public-safe Profile fields: username, display name, avatar path, and biography.
Anonymous profile exposure is not expanded merely because Follow exists.

Following never grants access to private Copies, WishlistIntent preferences,
precise geography, hidden collection rows, authentication metadata, or any
other private data. It does not change collection or WishlistIntent visibility.

The authenticated caller is always the follower for application writes. RLS
enforces that identity for inserts and permits deletion only of the caller's own
outgoing edges. There is no client update privilege because an edge has no
mutable state.

Follow and unfollow are idempotent application operations. Following an
existing edge returns that edge; unfollowing a missing edge succeeds as a no-op.
The primary key remains the concurrency authority.

## Reads and counts

Follower and following lists are bounded, paginated, and load their safe Profile
summary in the same query. Counts are calculated from the relation when read;
Geek stores no denormalized mutable counters.

Follow does not imply a trade relationship and does not affect Search or Match.
Activity feeds, notifications, recommendations, blocks, mutes, approval flows,
and feed ranking are future product work and are not part of this slice.
